## 1. เป้าหมายและคำถาม

แดชบอร์ดภาษาไทยบนเว็บ **3 แท็บ** ตอบ 3 คำถาม ใช้ข้อมูล 2 ชุด (รายได้ครัวเรือน สสช. + ดัชนีราคาที่อยู่อาศัย ธปท.) ช่วง **2554–2566**

| แท็บ | คำถามหลัก | ข้อมูล |
|---|---|---|
| **1 รายได้ครัวเรือน** | โครงสร้างและทิศทางรายได้ครัวเรือนไทยเป็นอย่างไร ใครอยู่ตรงไหนของความเหลื่อมล้ำทางพื้นที่ และพึ่งพารายได้จากแหล่งใดมากเกินไป เพื่อประเมินคุณภาพชีวิต | `income_ses` |
| **2 ดัชนีราคาบ้าน** | ราคาบ้านในแต่ละพื้นที่ของประเทศเปลี่ยนไปอย่างไร ภาคไหนและประเภทบ้านไหนโตเร็ว | `hpi_bot` |
| **3 รายได้ vs ราคาบ้าน** | ซื้อบ้านยากขึ้นหรือง่ายขึ้น เมื่อเทียบการเติบโตของรายได้กับราคาบ้าน | ทั้งสองชุด |

กราฟที่ต้องมีในระบบ: **choropleth, treemap, linear trend, heat map** (Tab 1–2) และ **เส้นอัตราส่วนดัชนี, แท่งคู่, แท่ง CAGR ×2** (Tab 3)

**เงื่อนไขร่วม (ผู้ใช้กำหนด)**
1. Backend เป็น **Python**
2. กราฟทั้งหมดใช้ **Plotly**
3. **ทุกกราฟในแท็บเดียวกันเชื่อมกัน**: เลือกอะไรในกราฟหนึ่ง กราฟอื่น ตัวเลข KPI สรุปและตารางอัปเดตตามทันที
4. ข้อมูลอยู่ใน **RDB** (`data/dashboard.db`)
5. สไตล์ **Modern** ใกล้เคียงภาพอ้างอิง แต่ **สลับโหมดมืด/สว่างได้** และ **เพิ่มสัดส่วนสีฟ้า**
6. ทุกกราฟมีปุ่ม **"สรุป"** ให้กดดูข้อสรุปจากข้อมูลของกราฟนั้นตามตัวกรองปัจจุบัน

## 3. สถาปัตยกรรม (แนะนำ)

```
Browser (HTML + CSS tokens + vanilla JS / Alpine + Plotly.js)
   │  GET /api/tab/{1|2|3}?filters…&theme=dark|light     (JSON: kpis, charts[plotly figure], summaries, table)
   ▼
FastAPI (app/main.py)  →  filters.py (validate)  →  db.py (sqlite3)  →  metrics.py (CAGR, rebase)
                                   └→ figures/*.py (plotly.graph_objects)  └→ summaries.py (templates ภาษาไทย)
   ▼
data/dashboard.db   (สร้างโดย etl/build_db.py)
```

- **Backend:** Python 3.11+, FastAPI + Uvicorn, `sqlite3` (หรือ SQLAlchemy 2 ถ้าจะย้าย PostgreSQL), pandas เฉพาะจัดรูปข้อมูล
- **กราฟ:** สร้างด้วย `plotly.graph_objects` ฝั่ง Python แล้วส่ง `fig.to_plotly_json()`; หน้าเว็บวาดด้วย Plotly.js (`Plotly.react`)
- **ทางเลือก:** Plotly Dash ทำได้ (callback ข้ามกราฟได้ในตัว) แต่ต้องรักษาเลย์เอาต์ ระบบสี โหมดมืด/สว่างและปุ่มสรุปตามสเปกนี้ → ตัดสินที่ D5
- **เหตุที่ให้ API คืนทุกกราฟของแท็บในครั้งเดียว:** ทำให้ตัวเลขทุกส่วนมาจากตัวกรองชุดเดียวกัน ไม่เหลื่อมกัน และสรุปอัตโนมัติตรงกับกราฟ
- **แคช:** `functools.lru_cache` ตามชุดตัวกรอง (ข้อมูลเล็ก คืนผลต่อคำขอ < 300 ms)

### 5.3 ตัวอักษรและรูปทรง
- **ฟอนต์:** `IBM Plex Sans Thai` (ข้อความ) · fallback `Noto Sans Thai`, `Sarabun`, `system-ui` · ตัวเลขใช้ `font-variant-numeric: tabular-nums` · ขนาด 12 / 14 / 16 / 20 / 28 / 40 px, หัวข้อ weight 600
- **รูปทรง:** การ์ดมุมโค้ง 20 px · ปุ่ม 12 px · ชิป pill · ตาราง 8 px · ระยะห่างตามกริด 8 px
- **ความลึก:** โหมดมืดใช้เส้นขอบ 1 px แทนเงา · โหมดสว่างใช้เงานุ่ม `0 1px 2px rgba(15,27,45,.06), 0 8px 24px rgba(15,27,45,.06)`
- **การเคลื่อนไหว:** เฉพาะตอบสนองการกด (150–200 ms) เช่น เปิดสรุป สลับธีม ไฮไลต์ภาค · เคารพ `prefers-reduced-motion`

### 5.4 โหมดมืด/สว่าง
1. ตั้ง `data-theme` บน `<html>`; ค่าเริ่มต้นตาม `prefers-color-scheme`; เก็บใน `localStorage['ihd-theme']`
2. สคริปต์สั้นใน `<head>` ตั้งธีมก่อน paint (กันจอกะพริบ)
3. ปุ่มสลับธีมที่แถบบนและในเมนูตั้งค่า (`aria-pressed`)
4. กราฟ: ส่ง `theme=dark|light` ให้ API สร้าง layout/สีตาม palette (ไม่ hard-code `plotly_dark`) พื้นหลังโปร่งใส ฟอนต์สีตาม `--text-muted` เส้นกริดสีตาม `--border` ผู้ใช้สลับธีม → เรียก API ซ้ำด้วยตัวกรองเดิม (ผลมาจากแคช)
5. เขียน `app/figures/theme.py` ให้เป็นที่เดียวที่รู้จักสี Plotly

### 5.5 ปุ่ม "สรุป" (✦) ในทุกกราฟ
- มุมขวาบนของการ์ดกราฟมี 3 ปุ่ม: **✦ สรุป** · **▤ ตาราง** (สลับเป็นตารางข้อมูลของกราฟนั้น ใช้เป็นทางเลือกสำหรับผู้ใช้โปรแกรมอ่านหน้าจอ) · **⤓ CSV**
- กด **สรุป** แล้วแผงเลื่อนเปิดใต้หัวกราฟ มี: ประโยคหลัก 1 ประโยค · 2–4 ข้อย่อย · บรรทัด **"ข้อควรระวัง"** จาก Data quality ที่เกี่ยวข้อง (เช่น Q-H1) · ปุ่ม **คัดลอก**
- **อัปเดตเองเมื่อตัวกรองเปลี่ยน** (ใช้ `aria-live="polite"`) จำสถานะเปิด/ปิดต่อกราฟไว้ใน `sessionStorage`
- สร้างฝั่ง Python ด้วย **เทมเพลตภาษาไทยที่กำหนดตายตัว** ไม่ใช้ LLM ทำให้ผลซ้ำได้และตรวจกับ `expected_values.json` ได้ (หัวข้อ 8)
- แผง Insights ด้านขวาแสดง "สรุปทั้งแท็บ" 3–5 ข้อ (ประกอบจากสรุปรายกราฟ)

## 6. ระบบตัวกรองและการเชื่อมกราฟ

### 6.1 สถานะร่วม (เก็บใน URL query เพื่อแชร์ลิงก์ได้)
`tab` · `year` (ปีเดียว) · `y0`,`y1` (ช่วงปีของกราฟแนวโน้ม) · `region` (0–5 หรือว่าง = ทุกภาค) · `area` (0/1/2, Tab 1) · `pt` (1/2/3, Tab 2–3) · `metric`, `grain` (ตัวเลือกของกราฟ) · `theme`

ค่าเริ่มต้น: `year=2566`, `y0=2554`, `y1=2566`, `region=` (ทุกภาค), `area=0`, `pt=1`

### 6.2 กติกาเชื่อมกราฟ
- **คลิกภาค** (ที่แผนที่ treemap แถวของ heat map แท่งภาค หรือเส้นในกราฟแนวโน้ม) → ตั้ง `region` ใหม่ กดซ้ำเพื่อยกเลิก
- **คลิกปี** (จุดบนเส้นแนวโน้ม คอลัมน์ของ heat map ชิปปี) → ตั้ง `year`
- **ไฮไลต์ vs กรอง:** กราฟที่ต้องเห็นบริบทหลายภาค (แนวโน้ม heat map แท่ง) **หรี่ภาคอื่น** ไม่ซ่อน · กราฟที่แสดงรายละเอียดของภาคเดียว (treemap) **กรองตามภาค**
- ตัวกรองมีผลเท่ากันทั้งหน้า ห้ามมีกราฟที่ไม่ตอบสนอง ยกเว้นที่ระบุ "ไม่ขึ้นกับ…" ในตารางข้างล่าง
- มีปุ่ม **ล้างทั้งหมด** และชิปตัวกรองที่แถบบน
- ถ้าชุดตัวกรองไม่มีข้อมูล (เช่น ทาวน์เฮ้าส์ + ภาคเหนือ) แสดงข้อความ "ไม่มีข้อมูลทาวน์เฮ้าส์ของภาคนี้" ในกราฟนั้น ไม่ใช่กราฟว่าง และไม่หยุดทั้งหน้า
